# PCLA (Plain Craft Launcher for Android)

**当前状态：** Alpha 0.1.0（早期开发阶段）
**开源协议：** AGPL-3.0
**核心语言：** Kotlin / Python

## 🌌 写在前面：一个 13 岁少年的赛博突围

你好，世界。我是这个项目的开发者，一个 13 岁的初中生。

我没有高配的电脑，没有昂贵的服务器，甚至连一把实体键盘都没有。我只有一部屏幕碎过、我自己动手换过屏的安卓手机。在一个几乎被认为不可能进行安卓原生开发的环境里，我靠着 Termux 终端、AI 辅助，以及 GitHub 免费提供的云端算力，硬生生敲出了这几千行代码。

我为什么要做 PCLA？因为我受够了。我受够了千元机玩家在手机上玩 Java 版 Minecraft 时，只能盲目地去猜配置；我受够了市面上那些所谓的“一键优化”噱头，除了发烫毫无作用。我想要一个真正懂底层、能用真实数据说话的启动器。

我不教你怎么调设置，我让启动器主动去“适配”你的手机。通过底层硬件探测与真机性能基线测试，用数据告诉你：你的手机，到底能跑多快。

这个项目不只是一个软件，它是一份证明——证明硬件的限制，永远无法困住一颗渴望探索的极客之心。

## 🛠️ 已完成的硬核工作（这不是画饼，是真实代码）

项目虽然尚未发布完整的客户端，但核心底层的“引擎”已现雏形：

- **底层设备智能探测（已实现）：** 基于 Kotlin 与 EGL14 离屏上下文技术，启动器能在后台毫秒级静默读取设备的 GL_RENDERER、GPU 型号及可用内存。不需要任何繁杂的权限，也不会打扰你，直接精准扒出你手机的硬件底细。
- **真机性能基线库（已建立）：** 我拿着测试机（MT6833V / 天玑 700）进行了极其严苛的压测。通过手写 Python 脚本解析庞大的 JVM GC 日志，对齐帧率谷底，得出了一个极其硬核的结论：“某些版本卡顿，真的不是你手机烂，而是 GC 停顿与渲染距离的锅！”
- **动态调度算法（开发中）：** 基于上述真实的测试数据，正在构建规则引擎。例如：探测到特定芯片，自动锁定推荐的渲染距离（RD）并注入最优的 JVM 启动参数，彻底杜绝“拉满画质导致手机变成暖手宝”的惨剧。

## 🧩 关于“缝合怪”的坦白与承诺

我必须极其坦诚地向开源社区和所有用户承认：现阶段，PCLA 的底层原生库（.so 文件）是一个“缝合怪”。

在移动端 MC 启动器的生态里，我们都站在巨人的肩膀上。因为我目前只有一部手机，在 Termux 里从零重写那些底层的 C/C++ 原生库简直比登天还难。我甚至无法在手机上查阅底层的 C/C++ 源码，移动端环境也根本不支持编译这些底层模块。因此，我借用并参考了部分 FCL (Fold Craft Launcher) 和 PojavLauncher 的底层原生库与渲染方案。

在此，我向 FCL 团队及所有移动端启动器的先驱们致以最崇高的敬意！没有你们的探索，就没有我这个项目的诞生。

但我在这里立下承诺：如果未来有一天，我有了自己的电脑，或者具备了足够的技术能力，我一定会从零开始重构所有的 .so 底层库，补上这一环！我会让 PCLA 成为一个真正纯粹、完全独立的项目！请开源社区的各位前辈和玩家见证我的成长。今天的缝合是暂时的，但我对技术的热爱是永恒的。
